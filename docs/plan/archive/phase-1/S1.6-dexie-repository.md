## State before the step

`dexie` is not installed. There is no `lib/db/` folder. The screens have no data
source.

## Goal

Every screen has one data interface. Every write and its outbox entry share one
transaction.

## Do

1. Install `dexie` and `dexie-react-hooks`.
2. Write `lib/db/dexie.ts`, version 1. Tables: `dailyEntries`, `profiles`, `outbox`,
   `syncMeta`. Index `dailyEntries` on `entry_date` and on `updated_at`.
3. Write `lib/db/repository.ts`. This is the only interface the screens use:

```ts
getDay(date: string): Promise<DailyEntry | undefined>
upsertDay(input: DailyEntryInput): Promise<DailyEntry>
listRange(from: string, to: string): Promise<DailyEntry[]>
softDeleteDay(date: string): Promise<void>
getProfile(): Promise<Profile>
updateProfile(patch: Partial<Profile>): Promise<Profile>
```

4. Every write does two things inside one Dexie transaction: it writes the row and it
   appends an outbox entry. Never one without the other.
5. The client generates the UUID with `lib/id.ts`, before the write. Never wait for
   the server.

## Acceptance criteria

- [ ] `upsertDay` creates a row and exactly one outbox entry.
- [ ] A second `upsertDay` on the same date updates the row, does not duplicate it,
      and appends a second outbox entry.
- [ ] The id of the updated row does not change.
- [ ] `listRange` returns rows in date order.
- [ ] `listRange` skips rows where `deleted_at` is not null.
- [ ] `getDay` returns undefined for a soft-deleted date.
- [ ] `softDeleteDay` sets `deleted_at` and appends an outbox entry. It never removes
      the row.
- [ ] A failure inside the transaction rolls back both the row and the outbox entry.
- [ ] `upsertDay` rejects input that fails the zod schema, before it opens the
      transaction.
- [ ] No file under `lib/db/` imports anything from `@supabase/*` or `lib/sync/`.

## Tests

Use `fake-indexeddb`. Reset the database between tests. Never share mutable state.

## Risk

A rollback test is easy to write wrongly. Force the failure inside the transaction,
not before it. Then assert both tables are unchanged.
