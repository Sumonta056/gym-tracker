## State before the step

The shell is wired. The repository works. `react-hook-form` and
`@hookform/resolvers` are not installed. There is no `/log` route.

## Goal

The user records a full day in one screen, offline, in under a minute.

## Do

1. Install `react-hook-form` and `@hookform/resolvers`.
2. Build the form from the mockup. The layout is: gym time and walk time side by
   side, the two heart rates side by side, weight with minus and plus buttons,
   calories and steps side by side, and a note field.
3. Use `react-hook-form` with the zod resolver from step 1.5.
4. `DurationField` shows the hint `Accepts 1:12:05, 72m or 1h 12m`. It shows the
   parsed value under the field as the user types.
5. Set `inputMode="decimal"` on weight. Set `inputMode="numeric"` on the counts.
6. Save writes through the repository. It never awaits the network.
7. Show the `OFFLINE` chip when the network is down. State that the data is safe.
8. At 1024 px and up, lay the fields out in two columns.

## Acceptance criteria

- [ ] An invalid duration blocks the save and names the problem in the error text.
- [ ] A max heart rate below the average blocks the save.
- [ ] The plus button changes the weight by 0.05. The minus button does the same in
      reverse.
- [ ] The weight never goes below the schema floor of 20.
- [ ] A successful save calls `upsertDay` exactly once, with parsed seconds, never
      with the raw text.
- [ ] The save handler does not await a network call.
- [ ] Every input has a `<label>` tied by `htmlFor`.
- [ ] Every error is tied to its input by `aria-describedby`, and the input carries
      `aria-invalid`.
- [ ] Opening `/log` for a date that already has an entry fills the form with it.
- [ ] Every tap target is 44 px or taller at 390 px.
