# Step 1.13b — Sync hardening: the dead-letter table

**Branch:** `feat/phase-1-daily-tracker` · **Size:** M · **Depends on:** 1.13
**Unlocks:** 1.15 · **Agent to run:** `sync-auditor` · **Skill to load:** `db-migration`,
`design-system`

Added after step 1.13. The owner ruled that a write that can never succeed must not
block the queue forever.

## Context to read first

1. `.claude/rules/architecture.md` — the UUID, outbox and soft delete rules.
2. `.claude/rules/testing.md` — write the tests first for `lib/sync/**`.
3. `lib/sync/worker.ts` — `push()` stops at the head of the queue. Backoff levels off at
   60 s.
4. `lib/db/dexie.ts` — the outbox table and `DATABASE_VERSION`.
5. `components/profile/SyncCard.tsx` from step 1.13.

## State before the step

The worker starts on app start, on the `online` event and every 30 s. One entry that
fails for good, for example a Row Level Security rejection `42501` or a server
constraint, blocks every later write forever.

## Goal

A write that can never reach the server moves out of the way, and the user sees it.

## Do

1. Add a `deadLetters` table to Dexie with a version bump. No Supabase change.
2. In `push()`, move an entry to `deadLetters` when its error code is permanent, or
   after a fixed number of attempts. The move and the outbox delete share one
   transaction. Keep the entry, its error code and its message.
3. Name the permanent codes in one place, with a test for each.
4. The queue then continues with the next entry.
5. `/profile` shows the dead-letter count with the chip in `Pending` or a danger
   state, and a short text. The user can retry one entry, or discard it.
6. Sign out also clears `deadLetters`.
7. Guard a second tab: two tabs never drain at the same time. Use `navigator.locks`
   or a `BroadcastChannel`.
8. Give `haltSync` a timeout, so sign-out never waits forever on a hung request.
9. The sign-out drain ignores the retry backoff, so the confirm sheet never offers to
   delete a write that would sync within a minute.
10. When the device is cleared but the server sign-out fails, the error text says that
    the data comes back from the server until sign-out succeeds.

## Acceptance criteria

- [ ] A permanent error moves the entry to `deadLetters` in one transaction, and the
      next entry syncs.
- [ ] A transient error keeps the entry at the head, with the backoff.
- [ ] After the attempt ceiling, the entry moves to `deadLetters`.
- [ ] Retry puts the entry back in the outbox with its original `id`. No duplicate row.
- [ ] Discard removes the entry. The local row keeps its data.
- [ ] Two tabs never run a drain at the same time.
- [ ] Sign-out finishes within the `haltSync` timeout, even with a hung request.
- [ ] A write in retry backoff syncs in the sign-out drain, not in the confirm count.
- [ ] The sign-out error text is true after a failed server sign-out.
- [ ] `lib/sync/**` coverage stays at 95 / 90 / 95 or higher.
