## State before the step

A saved set starts nothing. The user counts the rest in their head.

## Goal

After each set, a rest timer counts down to the right second, even after the phone
locks, and alerts at zero.

## Do

1. Write `lib/workout/restTimer.ts`, a pure function. The end time is the last set's
   `completed_at`, plus the rest seconds, plus 30 for each "+30 s" tap. The remaining
   time is the end time minus now, never below 0.
2. The rest seconds come from `rest_seconds_by_exercise[exerciseId]`. The default is 90.
3. Show the cyan card from the plate. It has Skip and +30 s.
4. Let the user change the rest time for this exercise from the card. Save it with
   `updateProfile`, so it syncs.
5. At zero, vibrate when `navigator.vibrate` exists, and play a short sound unless
   `rest_sound_muted` is on.
6. Add the mute toggle to `/profile`, in the units card or a new card as the plate
   shows.
7. Announce zero in an `aria-live="polite"` region, as text.

## Acceptance criteria

- [ ] The remaining time is correct after a simulated 60 second gap.
- [ ] A reload in the middle of a rest shows the correct remaining time.
- [ ] Skip clears the timer. +30 s raises it by 30.
- [ ] A changed rest time for one exercise applies to the next rest of that exercise
      only.
- [ ] With the mute setting on, no sound plays.
- [ ] Zero is announced as text, not by sound only.

## Risk

iOS Safari has no `navigator.vibrate`, and it plays a sound only after a user tap.
Unlock the audio on the "Add set" tap. The text alert is the one that always works.
Skip and +30 s live in memory, so a reload keeps the base rest but drops them. State
this in the report.
