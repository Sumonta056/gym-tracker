## State before the step

## Goal

A session starts, takes sets, and finishes on the device, with one outbox entry for
each write, in order.

## Do

Extend the repository:

```ts
getActiveSession(): Promise<WorkoutSession | undefined>
startSession(date: string): Promise<WorkoutSession>
finishSession(id: string): Promise<WorkoutSession>
discardSession(id: string): Promise<void>
addSet(input: WorkoutSetInput): Promise<WorkoutSet>
updateSet(id: string, patch: Partial<WorkoutSetInput>): Promise<WorkoutSet>
deleteSet(id: string): Promise<void>
restoreSet(id: string): Promise<void>
listSets(sessionId: string): Promise<WorkoutSet[]>
lastSetFor(exerciseId: string): Promise<WorkoutSet | undefined>
```

1. `startSession` sets `started_at` to now and `status` to `active`. It throws
   `SessionAlreadyActive` when an active session exists.
2. `finishSession` sets `ended_at` and `status = 'finished'`.
3. `discardSession` soft deletes the session and every set in it, in one transaction.
4. `addSet` gives the next `set_index` for that exercise in that session.
5. `deleteSet` soft deletes. `restoreSet` clears `deleted_at`. The undo in 2.4b uses
   it.
6. `lastSetFor` returns the newest set of an exercise across all sessions. The picker
   and "Add set" use it.
7. Every write shares one transaction with its outbox entry, and checks `signed_out`.

## Acceptance criteria

- [ ] `startSession` throws when a session is already active.
- [ ] `addSet` on an offline session queues the session and the set, the session
      first.
- [ ] `deleteSet` soft deletes and queues one entry. `listSets` then hides the set.
- [ ] `restoreSet` brings the set back and queues one entry.
- [ ] `discardSession` soft deletes the session and all its sets in one transaction.
- [ ] `lastSetFor` skips a soft-deleted set.
- [ ] A write on a signed-out device throws `SignedOutOnThisDevice`.

## Tests

One `it` for each criterion. Assert the outbox `sequence` order, not the array order.
