# Step 2.6 — Link a session to the day

**Branch:** `feat/phase-2-workout-log` · **Size:** S · **Depends on:** 2.4a
**Unlocks:** — · **Skill to load:** `design-system`

The daily row and the session measure the same gym time. This step joins them, but
never overwrites the user's own number without asking.

## Context to read first

1. `.claude/skills/design-system/` — load it first.
2. The finish and gym time offer plate from step 2.0.
3. `lib/db/repository.ts` — `getDay` and `upsertDay`.
4. `components/DailyEntryForm.tsx` — `/log`.

## State before the step

Finish ends the session. The day's `gym_seconds` does not change.

## Goal

After Finish, the day's Gym Time holds the session length, with the user's consent.

## Do

1. On Finish, compute the length as `ended_at` minus `started_at`, in whole seconds.
2. Offer to write it into the Gym Time of that day's `daily_entries` row.
3. If no row exists for that date, create one with only `gym_seconds` set.
4. If a row exists with a different `gym_seconds`, show both values and ask before
   the overwrite.
5. If the row already holds the same value, show no offer.
6. `/log` shows the same offer for a date that has a finished session and a different
   Gym Time.

## Acceptance criteria

- [ ] Finishing with no daily row creates one with the right seconds.
- [ ] Finishing with an existing row does not overwrite without consent.
- [ ] Declining the offer leaves the row as it was, and writes no outbox entry.
- [ ] `/log` shows the offer for such a date, and hides it after an accept.

## Tests
