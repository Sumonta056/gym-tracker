# Step 3.11 — The `coach-plan` skill

**Branch:** `feat/phase-3-coach-plans` · **Size:** M · **Depends on:** 3.3, 3.4, 3.10
**Unlocks:** 3.12 · **Skills to load:** `skill-creator`, `db-migration`

## Context to read first

1. `docs/specs/2026-09-24-coach-plans-design.md`, sections 6, 7 and 11 to 13.
2. `.claude/skills/db-migration/SKILL.md` — the shape of a project skill.
3. `scripts/exercise-image.mjs` from step 3.4 and `scripts/coach-data.mjs` from step
   3.2. The skill calls both. It never edits `lib/plans/coach.ts` by hand.
4. `docs/data/coach-exercises.json` and `docs/data/README.md`.

## State before the step

The 4 coach plans, their 52 images, their muscles and their video links are in the
app. A new plan or a new exercise needs a developer to repeat steps 3.2, 3.3 and 3.4
by hand.

## Goal

The owner gives a step, 2 image links and optionally a video link. The skill adds it
to the app with the image saved locally as WebP, the muscles looked up, and the data
file updated. There is no upload and no image hosting.

## Do

1. Write `.claude/skills/coach-plan/SKILL.md`. Its description names the triggers:
   "add an exercise", "add a step to a plan", "new plan from my coach", "change the
   image of", "set the video for", and a message with an image link and an exercise
   name.
2. The skill handles 5 requests:

   | Request                    | What changes                                                                          |
   | -------------------------- | ------------------------------------------------------------------------------------- |
   | Add a step to a plan       | 2 JPEG in `docs/data/coach-images/`, 2 WebP, 1 row in the JSON, a seed row if new     |
   | Change the image of a step | 1 or 2 JPEG and WebP files replaced. The paths stay the same.                         |
   | Set the video of a step    | `video` in the JSON row: the url, `kind: 'video'`, the length text                    |
   | Add a new plan             | A new `PlanId`, the plan in the JSON, its files, a migration for the `plan_ids` check |
   | Remove a step or a plan    | The step leaves the JSON. A plan gets `retired: true`, never a delete.                |

   Every request ends with `node scripts/coach-data.mjs`, which regenerates
   `lib/plans/coach.ts`.

3. The skill procedure:
   1. Collect the input: the plan, the group, the position, the name, the how-to text,
      the start image link, the end image link, and the video link if any.
   2. **Ask, never guess.** With 1 link only, ask if it is the start, the end, or one
      image that shows both. With no how-to text, ask for it. With no position, add
      the step at the end of the group.
   3. Look up the muscles: fetch Free Exercise DB `dist/exercises.json`, find the
      entry whose name matches best, show the owner the entry name and its primary
      and secondary lists, and wait for a yes. No match: ask the owner for the
      primary muscle from the `Muscle` enum.
   4. Show the owner a summary of the change. Wait for a yes.
   5. Make the slug from the name: lower case, a dash for each run of other
      characters. A slug that exists already means a change, not an add.
   6. Save the source images to `docs/data/coach-images/<slug>-<side>.jpg`. Run
      `node scripts/exercise-image.mjs <file> <slug> start`, then `end`.
   7. Open each new WebP file and look at it. Confirm that it shows the exercise. Say
      what it shows.
   8. Add the row to `docs/data/coach-exercises.json`, with a new UUID in `uuids`,
      written once as a literal. Run `node scripts/coach-data.mjs`.
   9. A new exercise: run the `db-migration` skill for 1 global seed row. A name that
      matches a seed row reuses that row's UUID and needs no migration.
   10. A new plan: add the id to `PlanId`, and run the `db-migration` skill to widen
       the `plan_ids` check.
   11. Run `pnpm test lib/plans lib/schema lib/design`. Then stop. Report the files
       changed. Never commit.
4. The skill's rules, written in the skill:
   - Only an `https` link, or a local file that the owner names. Only an image type.
     Refuse a file over 5 MB. A video link must be `https`.
   - Never write outside `docs/data/`, `public/exercises/`, `lib/plans/`,
     `lib/schema/plan.ts` and `supabase/migrations/`.
   - Never delete an image that another step still names.
   - Never remove a `PlanId`.
   - Copy the owner's how-to text word for word.
5. Add the skill to the table in `CLAUDE.md` and to the skills list under
   "The Claude workspace".

## Acceptance criteria

- [ ] Run the skill on `Squat` with its 2 files from `docs/data/coach-images/`. Git
      shows no change. This proves the conversion and the generator are stable.
- [ ] Run the skill with 1 link only. It asks which side the link is, and writes
      nothing before the answer.
- [ ] Run the skill to add a test exercise from 2 `https` links, on a scratch branch.
      It writes 2 JPEG, 2 WebP, 1 JSON row, the generated step and 1 migration, and
      the tests pass. Then delete the scratch branch.
- [ ] Run the skill to set a video on `Squat` on a scratch branch. The JSON row and
      the generated step carry it. Then delete the scratch branch.
- [ ] Run the skill with a link to a web page, not an image. It refuses.
- [ ] The skill never runs `git commit`.
