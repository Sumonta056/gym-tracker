# Step 3.11 — The `coach-plan` skill

**Branch:** `feat/phase-3-coach-plans` · **Size:** M · **Depends on:** 3.3, 3.4, 3.10
**Unlocks:** 3.12 · **Skills to load:** `skill-creator`, `db-migration`

## Context to read first

1. `docs/specs/2026-09-24-coach-plans-design.md`, sections 6 and 7.
2. `.claude/skills/db-migration/SKILL.md` — the shape of a project skill.
3. `scripts/exercise-image.mjs` from step 3.4. The skill calls it. It never converts
   an image another way.
4. `lib/schema/plan.ts` and `lib/plans/coach.ts` from step 3.2.

## State before the step

The 4 coach plans and their 52 images are in the app. A new plan or a new exercise
needs a developer to repeat steps 3.2, 3.3 and 3.4 by hand.

## Goal

The owner gives an image link and a step. The skill adds it to the app, with the
image saved locally as WebP. There is no upload and no image hosting.

## Do

1. Write `.claude/skills/coach-plan/SKILL.md`. Its description names the triggers:
   "add an exercise", "add a step to a plan", "new plan from my coach", "change the
   image of", and a message with an image link and an exercise name.
2. The skill handles 4 requests:

   | Request                    | What changes                                                                            |
   | -------------------------- | --------------------------------------------------------------------------------------- |
   | Add a step to a plan       | 2 WebP files, 1 step in `coach.ts`, a seed row if it is new                             |
   | Change the image of a step | 1 or 2 WebP files replaced. The paths stay the same.                                    |
   | Add a new plan             | A new `PlanId`, the plan in `coach.ts`, its files, a migration for the `plan_ids` check |
   | Remove a step or a plan    | The step leaves `coach.ts`. A plan gets `retired: true`, never a delete.                |

3. The skill procedure:
   1. Collect the input: the plan, the group, the position, the name, the how-to text,
      the start image link and the end image link.
   2. **Ask, never guess.** With 1 link only, ask if it is the start, the end, or one
      image that shows both. With no how-to text, ask for it. With no position, add
      the step at the end of the group.
   3. Show the owner a summary of the change. Wait for a yes.
   4. Make the slug from the name: lower case, a dash for each run of other
      characters. A slug that exists already means a change, not an add.
   5. Run `node scripts/exercise-image.mjs <link> <slug> start`, then `end`.
   6. Open each new WebP file and look at it. Confirm that it shows the exercise. Say
      what it shows.
   7. Edit `lib/plans/coach.ts`. A new exercise gets a new UUID, written once as a
      literal. Write both `images` paths in full. The target is 3 × 10–12 unless the
      owner gives one.
   8. A new exercise: run the `db-migration` skill for 1 global seed row. A name that
      matches a seed row reuses that row's UUID and needs no migration.
   9. A new plan: add the id to `PlanId`, and run the `db-migration` skill to widen the
      `plan_ids` check.
   10. Run `pnpm test lib/plans lib/schema`. Then stop. Report the files changed. Never
       commit. The normal gate runs later: `pnpm verify`, the `commit-report` skill,
       then the owner's commit.
4. The skill's rules, written in the skill:
   - Only an `https` link, or a local file that the owner names. Only an image type.
     Refuse a file over 5 MB.
   - Never write outside `public/exercises/`, `lib/plans/`, `lib/schema/plan.ts` and
     `supabase/migrations/`.
   - Never delete an image that another step still names.
   - Never remove a `PlanId`.
   - Copy the owner's how-to text word for word.
5. Add the skill to the table in `CLAUDE.md` and to the skills list under
   "The Claude workspace".

## Acceptance criteria

- [ ] Save the 2 original `Squat` images from `docs/My Gym Plan.html` as local files.
      Run the skill on `Squat` with them. Git shows no change. This proves the
      conversion gives the same bytes each time.
- [ ] Run the skill with 1 link only. It asks which side the link is, and writes
      nothing before the answer.
- [ ] Run the skill to add a test exercise from 2 `https` links, on a scratch branch.
      It writes 2 WebP files, 1 step and 1 migration, and the tests pass. Then delete
      the scratch branch.
- [ ] Run the skill with a link to a web page, not an image. It refuses.
- [ ] The skill never runs `git commit`.
