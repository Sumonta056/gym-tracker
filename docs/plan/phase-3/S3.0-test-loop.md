# Step 3.0 — The step test loop

**Branch:** `feat/phase-3-coach-plans` · **Size:** S · **Depends on:** the fix track
**Unlocks:** 3.1

## Context to read first

1. `package.json`, the `check:step`, `e2e` and `verify` scripts.
2. `scripts/test-changed.mjs` — how `check:step` picks the tests.
3. `playwright.config.ts` — the `desktop` project and the reused e2e build.
4. `.claude/rules/testing.md`, "The gate".

## State before the step

Every step ends with `pnpm verify`: the static checks, all 203 unit files with
coverage, the full build, and 230 e2e tests on 3 browsers. Under Mac load the e2e part
alone passes 20 minutes.

## Goal

A step proves its own change in minutes. The full gate still runs at the checkpoints,
before the merge, and in CI on every push.

## Do

1. Add to `package.json`:
   ```
   "e2e:step": "nice -n 10 playwright test --project=setup --project=desktop"
   ```
   It takes the spec as an argument: `pnpm e2e:step tests/e2e/plans.spec.ts`. The
   `setup` project signs in first, as the full suite does.
2. In `.claude/rules/testing.md`, under "The gate", add:
   > In Phase 3 a step runs `pnpm check:step`, then `pnpm e2e:step <spec>` for the spec
   > its step file names. The full `pnpm verify` runs at each checkpoint and before the
   > merge to `main`.
3. In `PROGRESS.md`, rule 3 under "Rules that block you" says the same.
4. In `.claude/skills/commit-report/SKILL.md`, the evidence section accepts the output
   of `check:step` and `e2e:step` for a Phase 3 step.

## Acceptance criteria

- [ ] `pnpm e2e:step tests/e2e/smoke.spec.ts` runs the setup project and the smoke
      spec on desktop only, and passes.
- [ ] `pnpm e2e:step` with no argument runs every spec on desktop. Acceptable.
- [ ] The 3 documents name the loop.

## Verification

1. `pnpm check:step`.
2. `pnpm e2e:step tests/e2e/smoke.spec.ts`.
