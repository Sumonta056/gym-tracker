## State before the step

No plan exists in code. The coach plan lives in `docs/data/coach-exercises.json`.

## Goal

The 4 coach plans are typed, tested data that every later step reads, generated from
the data folder so a data change never needs a hand edit.

## Do

1. `lib/schema/plan.ts`:
   - `PlanId`: the enum `chest-triceps`, `back-biceps`, `shoulders`, `legs`.
   - `Muscle`: the enum of the 16 Free Exercise DB names in `docs/data/README.md`.
   - `PlanStep`: `exerciseId` (uuid), `slug`, `name`, `how`, `images`, `muscles`,
     `video` and `target`.
     - `images` has `start` and `end`. Each must match
       `^/exercises/[a-z0-9-]+-(start|end)\.webp$`.
     - `muscles` has `primary`, 1 or more `Muscle`, and `secondary`, 0 or more.
     - `video` is optional: `{ url: string, kind: 'search' | 'video', length?: string }`.
       The url must start with `https://`.
     - `target` has `sets`, `repsMin` and `repsMax`.
   - `PlanGroup`: `name` and `steps`, 1 or more.
   - `Plan`: `id`, `title`, `groups`, 1 or more, and `retired`, default false.
   - Never remove an id from `PlanId`. Old sessions carry it. Retire the plan instead.
2. `scripts/coach-data.mjs`: reads `docs/data/coach-exercises.json` and writes
   `lib/plans/coach.ts`. It maps each `docs/data/coach-images/<slug>-<side>.jpg` to
   `/exercises/<slug>-<side>.webp`, copies `muscles`, `video`, `name`, `how` and the
   order, and sets every `target` to `{ sets: 3, repsMin: 10, repsMax: 12 }`. It
   writes a fixed UUID per slug from a `uuids` map inside the JSON. Add that map now:
   26 UUIDs, written once, never generated at run time. Run it. Commit its output.
   The script also writes `lib/design/body.ts` for step 3.4b, so run it again there.
3. `lib/plans/index.ts`:
   ```ts
   listPlans(): Plan[]                     // hides a retired plan
   getPlan(id: PlanId): Plan | undefined   // finds a retired plan too
   planSteps(plan: Plan): PlanStep[]
   planMinutes(plans: Plan[]): number      // 5 per step plus 10 per plan
   combinePlans(ids: string[]): { title: string; steps: PlanStep[] }
   ```
   `combinePlans` keeps the order of `ids`, drops an unknown id, drops a repeated step
   and keeps the first. Its title joins the plan titles with `+`.
4. No image helper. The screens read `step.images` as it is.

## Acceptance criteria

- [ ] `lib/plans/coach.ts` parses with the `Plan` schema.
- [ ] There are 4 plans and 26 steps: 9, 9, 5 and 3.
- [ ] Every `slug`, every `exerciseId` and every UUID in the JSON is unique.
- [ ] Every `name` and `how` equals the text in `docs/data/coach-exercises.json`.
- [ ] Every step has 1 or more primary muscles, and every muscle is in `Muscle`.
- [ ] Every step has a `video.url` that starts with `https://`.
- [ ] `combinePlans(['shoulders', 'legs'])` returns 8 steps, shoulders first, and the
      title `Shoulders + Legs`.
- [ ] `combinePlans(['legs', 'nope'])` returns the 3 legs steps. `combinePlans([])`
      returns 0 steps.
- [ ] `planMinutes` gives 55, 55, 35 and 25 for the 4 plans, and 60 for shoulders and
      legs together.
- [ ] `listPlans()` hides a plan with `retired: true`. `getPlan` still finds it.
- [ ] Running `scripts/coach-data.mjs` twice leaves no change in git.
- [ ] No file under `lib/plans/` imports `@supabase/*`, `lib/sync/` or `lib/db/`.
