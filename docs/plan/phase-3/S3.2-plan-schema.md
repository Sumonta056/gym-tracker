# Step 3.2 — The plan schema and the coach data

**Branch:** `feat/phase-3-coach-plans` · **Size:** M · **Depends on:** 3.1
**Unlocks:** 3.3, 3.4, 3.5

## Context to read first

1. `docs/specs/2026-09-24-coach-plans-design.md`, sections 5 and 6.
2. `docs/My Gym Plan.html` — the `plan` array in its script. This is the source.
3. `lib/schema/` — the Phase 2 exercise schema. Reuse its muscle group enum.

## State before the step

No plan exists in code. The coach plan lives only in the HTML file.

## Goal

The 4 coach plans are typed, tested data that every later step reads.

## Do

1. `lib/schema/plan.ts`:
   - `PlanId`: the enum `chest-triceps`, `back-biceps`, `shoulders`, `legs`.
   - `PlanStep`: `exerciseId` (uuid), `slug`, `name`, `how`, `images` and `target`.
     `images` has `start` and `end`. Each must match
     `^/exercises/[a-z0-9-]+-(start|end)\.webp$`. `target` has `sets`, `repsMin` and
     `repsMax`.
   - `PlanGroup`: `name` and `steps`, 1 or more.
   - `Plan`: `id`, `title`, `groups`, 1 or more, and `retired`, default false.
   - Never remove an id from `PlanId`. Old sessions carry it. Retire the plan instead.
2. `lib/plans/coach.ts`: the 4 plans. Copy every name and every `how` text word for
   word. Keep the coach's order. Every `target` is `{ sets: 3, repsMin: 10, repsMax: 12 }`.
   Write both `images` paths on every step, in full. The files arrive in step 3.4.
3. Give each of the 26 exercises a fixed UUID. Write each UUID by hand once. Never
   generate one at run time.
4. `lib/plans/index.ts`:
   ```ts
   listPlans(): Plan[]                     // hides a retired plan
   getPlan(id: PlanId): Plan | undefined   // finds a retired plan too
   planSteps(plan: Plan): PlanStep[]
   combinePlans(ids: string[]): { title: string; steps: PlanStep[] }
   ```
   `combinePlans` keeps the order of `ids`, drops an unknown id, drops a repeated step
   and keeps the first. Its title joins the plan titles with a
   space, a plus sign and a space, for example `Shoulders + Legs`.
5. No image helper. The screens read `step.images` as it is.

## Acceptance criteria

- [ ] `lib/plans/coach.ts` parses with the `Plan` schema.
- [ ] There are 4 plans and 26 steps: 9, 9, 5 and 3.
- [ ] Every `slug` and every `exerciseId` is unique.
- [ ] Every `name` and `how` equals the text in `docs/My Gym Plan.html`.
- [ ] `combinePlans(['shoulders', 'legs'])` returns 8 steps, shoulders first, and the
      title `Shoulders + Legs`.
- [ ] `combinePlans(['legs', 'nope'])` returns the 3 legs steps.
- [ ] `combinePlans([])` returns 0 steps.
- [ ] Every step's `images.start` and `images.end` use its own `slug`.
- [ ] `listPlans()` hides a plan with `retired: true`. `getPlan` still finds it.
- [ ] No file under `lib/plans/` imports `@supabase/*`, `lib/sync/` or `lib/db/`.

## Tests

- `lib/schema/plan.test.ts`: a valid plan parses. A step with `repsMin` above
  `repsMax` fails.
- `lib/plans/coach.test.ts`: the counts, the unique ids, and the text check against
  the HTML source. Read the file with `fs` in the test.
- `lib/plans/index.test.ts`: each `combinePlans` case above, and the retired rule.
- `lib/schema/plan.test.ts`: an image path outside `/exercises/` fails.
