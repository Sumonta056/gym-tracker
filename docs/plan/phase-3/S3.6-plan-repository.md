## State before the step

The database has `plan_ids` and `planCursors`. The repository does not use them.

## Goal

The screens can start a plan, keep their place, and fill the rows, through the
repository only.

## Do

1. Extend `lib/db/repository.ts`:
   ```ts
   startPlanSession(planIds: PlanId[], date: string): Promise<WorkoutSession>
   getPlanCursor(sessionId: string): Promise<PlanCursor | undefined>
   setPlanCursor(cursor: PlanCursor): Promise<void>
   clearPlanCursor(sessionId: string): Promise<void>
   lastSetFor(exerciseId: string): Promise<WorkoutSet | undefined>
   listPlanHistory(): Promise<WorkoutSession[]>
   ```
2. `startPlanSession` uses the same path as the Phase 2 `startSession`. It sets
   `plan_ids` and writes the session and its outbox entry in one transaction. It
   validates `planIds` with the schema first.
3. The cursor functions write `planCursors` only. No outbox entry.
4. `lastSetFor` returns the newest set of that exercise from a finished session,
   `deleted_at` null.
5. `finishSession` also clears the cursor of that session.
6. The sync worker pushes and pulls `plan_ids` with the rest of the session row.
7. `clearAll` on sign-out also clears `planCursors`.

## Acceptance criteria

- [ ] `startPlanSession` writes 1 session and 1 outbox entry.
- [ ] `startPlanSession` fails when a session is already active.
- [ ] `startPlanSession(['foo'])` rejects before it opens the transaction.
- [ ] `setPlanCursor` writes no outbox entry.
- [ ] `finishSession` clears the cursor.
- [ ] `lastSetFor` skips a soft-deleted set and a set from the active session.
- [ ] A pulled session keeps its `plan_ids`.
- [ ] Sign-out leaves `planCursors` empty.
- [ ] No screen code imports `lib/sync/**` or `@supabase/*`.
