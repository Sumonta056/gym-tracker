# Step 1.16b — Sync follow-ups: the sign-out limits

**Branch:** `feat/phase-1-daily-tracker` · **Size:** M · **Depends on:** 1.16
**Unlocks:** 1.17 · **Agent to run:** `sync-auditor`

Added after step 1.15. Step 1.13b left five known limits in the sign-out path. They
were listed under 1.15, but 1.15 is a UI step. The owner moved them here.

## Context to read first

1. `.claude/rules/architecture.md` — the UUID, outbox and soft delete rules.
2. `.claude/rules/testing.md` — write the tests first for `lib/sync/**`.
3. `docs/plan/phase-1/S1.13b-sync-hardening.md` and its report,
   `reports/2026-09-24-sync-dead-letters-drain-guards.html`.
4. `lib/sync/worker.ts`, `lib/db/repository.ts` and `lib/auth/**` — `DRAIN_LOCK`,
   `clearAll`, the 15 s sign-out marker and the dead-letter cap.

## State before the step

Sign-out drains, holds `DRAIN_LOCK` across the clear and the server sign-out, and
leaves a 15 s marker for other tabs. A refused write moves to `deadLetters`.

## Goal

Each of the five limits is closed, or kept on purpose with a written reason.

## Do

For each limit, write the failing test first, then fix it or record why it stays.

1. `clearAll` waits on `DRAIN_LOCK` with no timeout.
2. The dead-letter cap of 3 in a row resets each turn.
3. A save in another tab after the clear, before sign-out ends, stays on the device.
4. A re-sign-in within 15 s of a sign-out waits for its first sync.
5. With no Web Locks and a blocked `localStorage`, another tab can refill the device.

## Acceptance criteria

- [ ] Each limit has a test that failed before its fix, or a named reason in
      `.claude/rules/architecture.md` for why it stays.
- [ ] No write is lost and no row is duplicated. The `sync-auditor` agent reports
      nothing.
- [ ] `lib/sync/**` stays at 95 lines, 90 branches, 95 functions or better.
- [ ] `pnpm verify` passes.

## When the step is done

1. `pnpm verify`
2. The `commit-report` skill.
3. Commit `fix(sync): close the sign-out limits`
4. Set **Next step** in `PROGRESS.md` to `1.17`.
