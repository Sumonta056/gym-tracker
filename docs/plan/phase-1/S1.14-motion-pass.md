# Step 1.14 — The motion pass

**Branch:** `feat/phase-1-daily-tracker` · **Size:** S · **Depends on:** 1.12
**Unlocks:** 1.15 · **Skill to load:** `design-system`

## Context to read first

1. `.claude/skills/design-system/` — the motion section.
2. `.claude/rules/accessibility.md` — motion must never block a value.

## State before the step

Every Phase 1 screen works with no animation. `motion` is not installed.

## Goal

The app feels alive, and it stays usable for a user who turns motion off.

## Do

1. Install `motion`.
2. Count the hero number up on the dashboard when it first appears.
3. Draw the chart lines in over 400 ms, on first paint only, never on a re-render.
4. Fade and slide the page transitions, 180 ms.
5. Add a short press feedback to the tab bar buttons.
6. Respect `prefers-reduced-motion`. When it is set, show the end state at once.

## Acceptance criteria

- [ ] With reduced motion set, no animation runs.
- [ ] With reduced motion set, the final hero value is in the document immediately.
- [ ] A dashboard re-render does not replay the count-up.
- [ ] A chart re-render does not replay the line draw.
- [ ] No animation delays a tap. Every button responds at once.
- [ ] No animation causes a layout shift.

## Tests

- Component: with reduced motion set, no animation runs and the final value is in the
  document immediately.
- Component: a second render does not restart the count-up.

## Verification

1. `pnpm verify`.
2. Manual at 390 px: the transitions read as smooth, not slow.

## Files touched

- `components/dashboard/*`
- `components/charts/*`
- `components/ui/AppShell.tsx`
- `app/(app)/layout.tsx`
- `package.json`

## Risk

An animated value that is absent from the document until the animation ends fails
the accessibility rule. Render the final value, then animate the display of it.

## When the step is done

1. `pnpm verify`
2. The `commit-report` skill.
3. Commit `feat(ui): add the motion pass with reduced motion support`
4. Set **Next step** in `PROGRESS.md` to `1.15`.
