# Step 1.17 — Deploy and the real device check

**Branch:** `feat/phase-1-daily-tracker` · **Size:** S · **Depends on:** 1.16
**Unlocks:** Phase 2

This step needs the user. It needs a real iPhone, a Vercel account and a real
network. Stop and ask before each part that the user must do.

## Context to read first

1. `docs/plan/01-phase-1.md`, the Phase 1 checklist at the end.
2. `.env.example` from step 1.1 — the variables Vercel needs.

## State before the step

Every screen, every test and every gate is green on the laptop. Nothing is deployed.

## Goal

The app runs from the iPhone home screen, survives flight mode, and shows the same
data on the laptop.

## Do

1. Deploy to Vercel. Set the environment variables in the Vercel project.
2. Ask the user to open the deployed URL in Safari on a real iPhone. Then Share, then
   Add to Home Screen.
3. Ask the user to open it from the home screen.
4. Ask the user to turn on flight mode, record a day, then turn flight mode off.
5. Ask the user to open the same URL on the laptop.

## Acceptance criteria

- [x] The deployment is live and the sign-in works on it.
- [x] The app opens from the iPhone home screen with no browser chrome.
- [x] The safe area is respected. The tab bar is not under the home indicator.
- [x] A day recorded in flight mode appears at once in the app.
- [x] The chip reads `OFFLINE` while flight mode is on.
- [x] After flight mode ends, the chip turns green and the row reaches Supabase.
- [x] The laptop shows the sidebar layout and the same data.
