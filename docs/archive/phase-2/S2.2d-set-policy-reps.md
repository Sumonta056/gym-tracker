# Step 2.2d — The set policy and the reps constraint

**Branch:** `feat/phase-2-workout-log` · **Size:** S · **Depends on:** 2.2c
**Unlocks:** Checkpoint A · **Agents to use:** `sync-auditor`

Step 2.2c found 2 gaps in the server schema. This step closes both in one migration.
It changes no Dexie table, so it needs no Dexie bump.

## Context to read first

1. `.claude/rules/architecture.md` — the Row Level Security rule.
2. `supabase/migrations/20260927142258_phase2_workouts.sql` — the `workout_sets`
   policies and columns.
3. `.claude/skills/db-migration/`.
4. `lib/schema/` — the `workout_sets` zod schema, reps 1 to 1000.

## State before the step

- The `workout_sets` insert and update policies check only the session owner. A set
  can point to an exercise that belongs to another user. Only the foreign key applies.
- `workout_sets.reps` is nullable on the server. The client requires 1 to 1000. The
  pull maps null to 1.

## Goal

The server refuses a set that points to an exercise of another user, and a set with
reps outside 1 to 1000.

## Do

1. Write `supabase/migrations/<YYYYMMDDHHMMSS>_phase2_set_policy_reps.sql`.
2. Recreate the `workout_sets` insert and update policies. Add to each `with check`:

   ```sql
   exists (select 1 from exercises e where e.id = workout_sets.exercise_id
     and (e.user_id = auth.uid() or e.user_id is null))
   ```

3. `alter column reps set not null` and add `check (reps between 1 and 1000)`. First
   count the rows that break either rule. If any exist, stop and report them.
4. Apply the migration through the Supabase MCP tools. Rename the local file to the
   version that `list_migrations` shows.
5. Run `get_advisors` for security. Report any new warning.

## Acceptance criteria

- [ ] An insert of a set that points to an exercise of another user is refused.
- [ ] An insert of a set that points to a global exercise is accepted.
- [ ] An insert with reps null, 0 or 1001 is refused.
- [ ] The existing rows still pass every check.

## Tests

By hand, through the MCP SQL tool, inside a transaction that rolls back. Set the
`request.jwt.claims` for 2 test users.

## Risk

A policy with a wrong `exists` refuses every set, and the worker moves each one to
`deadLetters`. Test the global exercise case before you apply.
