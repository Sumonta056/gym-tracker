## State before the step

Sessions and sets exist. `/analytics` shows the Phase 1 charts only.

## Goal

The user sees whether each lift goes up, on a phone and on a laptop.

## Do

1. Add 2 read functions to the repository: `listSessions(from, to)` and
   `listSetsInRange(from, to)`. Both hide soft-deleted rows.
2. Volume load per session: bars, with the change against the previous week as text.
3. Estimated one-rep max per exercise: one line per selected exercise. The user picks
   up to 3 exercises with a toggle group.
4. The personal record list, as the plate shows: the best load, the best volume, the
   date, and the estimated one-rep max.
5. Every chart reads colors from `lib/design/tokens.ts`, uses `ResponsiveContainer`,
   and has a `role="img"` with an `aria-label` that states the trend in words.

## Acceptance criteria

- [ ] Each chart renders its empty state before any session exists.
- [ ] Each chart renders with one session, with no lone dot.
- [ ] The record list matches a hand calculation for one exercise.
- [ ] No chart sets a fixed pixel width. No raw hex.
- [ ] Every chart follows `charts.md`: day labels, value labels, an average line, and
      the "not enough data" state.
- [ ] One chart per row at 390 px. Two per row at 1440 px.
