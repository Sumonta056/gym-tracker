## State before the step

The three Supabase clients exist. `app/page.tsx` is the Phase 0 placeholder. There is
no `middleware.ts` and there are no route groups.

## Goal

An anonymous visitor lands on `/sign-in`. A magic link signs the user in and returns
them to the app.

## Do

1. Write `middleware.ts` at the repository root. It refreshes the session and
   redirects an anonymous visitor to `/sign-in`.
2. Create the route groups. Move the signed-in routes under `app/(app)/`. Put
   `app/(auth)/sign-in/page.tsx` in the auth group.
3. Build the sign-in screen from the mockup. It holds the dumbbell mark, the title,
   the email field, the send button, the install hint card and the two trust chips.
4. Write the callback at `app/auth/callback/route.ts`.
5. Add a "check your email" state after a send.

## Acceptance criteria

- [ ] An anonymous request to `/` returns a redirect to `/sign-in`.
- [ ] The email field has a `<label>` tied by `htmlFor`.
- [ ] An invalid email shows an error and the form does not submit.
- [ ] The error is tied to the input by `aria-describedby`. The input carries
      `aria-invalid`.
- [ ] While the request is in flight, the button is disabled and shows a pending
      state.
- [ ] After a send, the screen shows the "check your email" state.
- [ ] The callback route exchanges the code and redirects to `/`.
- [ ] Every tap target on the screen is 44 px or taller at 390 px.

## Tests to write

- Component: the form shows an error for an invalid email and does not submit.
- Component: the button is disabled and shows a pending state while sending.
- E2E: an anonymous visit to `/` lands on `/sign-in`.
