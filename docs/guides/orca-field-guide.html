Orca Field Guide

Orca puts each worktree, its terminals, a browser tab and a phone emulator in one left bar. Claude can drive every panel with the orca CLI. Each section gives the words to say to Claude and the commands that run behind them.

Browser tab

The tab belongs to a worktree. A snapshot gives each element a ref such as @e3. A ref is valid until the page changes, so take a new snapshot after each click that changes the page.

Say to Claude
  • Open Stats in the Orca tab and switch Day, Week, Month. Tell me if anything flickers.
  • Start a session, log 1 set of bench 60 × 8, finish it, then check that Today counts it.
  • Read the console errors of the Orca tab.
  • Read this week's workoutSessions from IndexedDB.
Runs 
orca tab list --json
orca goto --url http://localhost:3000/analytics --json
orca wait --load networkidle --json
orca snapshot --json              # refs @e1, @e2 …
orca click --element @e5 --json
orca fill --element @e7 --value "60" --json
orca screenshot --json
orca console --limit 50 --json
orca eval --expression "location.href" --json

Design Mode. In the Orca browser, click any element to send its HTML, CSS and a cropped screenshot straight into the agent prompt. Use it for "make this card match the prototype".

Terminals

Every terminal has a handle. Claude reads a terminal before it sends input, and uses wait --for tui-idle to know when an agent such as Claude Code has finished its turn.

Say to Claude
  • Read the last 50 lines of the terminal in the gym-tracker-c3 worktree.
  • Split my terminal and run pnpm test --watch in the new pane.
  • Wait until the agent in worktree A3 is idle, then tell me what it said.
  • Send "go" to the B2 agent's terminal.
Runs 
orca terminal list --json
orca terminal read --terminal <handle> --json
orca terminal send --terminal <handle> --text "go" --enter --wait-submit 10 --json
orca terminal wait --terminal <handle> --for tui-idle --timeout-ms 600000 --json
orca terminal split --direction horizontal --command "pnpm test --watch" --json
orca terminal rename --terminal <handle> --title "Wave 3 coordinator" --json

Splits. --direction horizontal splits left and right. --direction vertical splits top and bottom.

Worktrees

A worktree is a card in the left bar. Create it with --agent and the agent starts in its first terminal with your prompt. The card comment and status tell you where each agent is without opening it.

Say to Claude
  • Show all worktrees and which ones have running agents.
  • Set this card's comment to "wave 2 merged, waiting for iPhone check".
  • Mark this worktree in-review and set the unread dot.
Runs 
orca worktree ps                 # agents, last output, status
orca worktree current --json
orca worktree set --worktree active \
  --comment "wave 2 merged, waiting for iPhone check" \
  --workspace-status in-review --unread --json
orca worktree create --name a3-error-log --base-branch fix/feedback-fixes \
  --agent claude --prompt "Do the step in docs/plan/feedback/A3-error-log.md." --json

Files and diffs

Say to Claude
  • Open the B2 diff of the workouts page as a tab.
  • Open every changed file of this worktree.
Runs 
orca file diff --path "app/(app)/workouts/page.tsx" --focus
orca file open-changed

Annotate the diff. In the diff tab, add an inline comment on a line and send it back to the agent as feedback.

Emulator

The iOS Simulator shows live in the emulator pane. It needs the full Xcode app. Coordinates are fractions from 0 to 1, from the top left.

Say to Claude
  • Check B2 in the simulator, before and after F5.
  • Open the app on the iPhone 16 simulator and screenshot /workout.
Runs 
orca emulator attach "iPhone 16" --json
xcrun simctl openurl booted http://localhost:3000
orca emulator ax --json           # accessibility tree with frames
orca emulator tap 0.5 0.92 --json
orca emulator type "hello" --json
orca emulator button home --json
orca emulator kill --json

Orchestration

For coordinated work, agents talk through a run with a mailbox, tasks and decision gates, instead of raw terminal input. A worker can ask the coordinator a blocking question and wait for the reply. 

orca orchestration run-create --json
orca orchestration task-create --json
orca orchestration dispatch --json         # send a task to a terminal
orca orchestration ask --json              # worker → coordinator, blocks
orca orchestration reply --json
orca orchestration gate-create --json      # an owner decision blocks a task
orca orchestration gate-resolve --json
orca orchestration inbox --json

Fit for the fix track. The owner questions of B2 and C3 map to decision gates: the task waits until the gate resolves, and the answer is on record.

How others use it

Patterns from the Orca README and community tutorials.

Fan out and pick the best

Send 1 prompt to several agents, each in its own worktree. Compare the diffs and merge the best one.

Setup on create

Let the repo setup hook run pnpm install in each new worktree, so an agent starts with dependencies ready.

Work from the ticket

Connect GitHub or Linear and open a worktree straight from an issue. The card links back to it.

Design Mode for UI fixes

Click the broken element in the Orca browser. Its HTML, CSS and a cropped screenshot go into the prompt.

Remote muscle

SSH worktrees run agents on a stronger machine, with port forwarding and auto-reconnect. Useful when 3 e2e suites overload a laptop.

Notifications

Turn on desktop and mobile alerts, then work on something else until an agent finishes.

Rules of thumb

Take a new snapshot after every navigation or page change. Old refs fail with browser_stale_ref.
Read a terminal before you send to it. You see what the agent is doing first.
Use 1 handle per agent. After an Orca restart, list the terminals again and use only the new handle.
Never resend a prompt because nothing happened. Use --wait-submit to prove the prompt started.
Sleep a workspace instead of closing it. Sleep keeps the terminals and agent sessions for later.
Run orca emulator kill when done. A running helper holds the device until Orca quits.
